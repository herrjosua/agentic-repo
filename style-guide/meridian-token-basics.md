## Overview
**Evidence basis:** Mixed. Observed: the 8 token names, values and types, copied from `design-tokens/tokens.tokens.json:4-5,8-9,13-15,18`, and the colour notes from `design-tokens/design.md:9-12`; the no-colour-only rule, quoted from `design-system/v4-1-status-indicator-component.md:31-33`. Inferred or Illustrative: none of the usage below is recorded beyond those notes, and this guide adds no usage guidance of its own.

The design tokens as the repo records them: 4 colour, 3 spacing and 1 radius token. Values are
copied from `design-tokens/tokens.tokens.json`, the canonical token source, which is generated by
the Figma sync; `design-tokens/design.md` is its generated view. If the two ever differ from this
guide, they win. The token file names no product, so "Meridian" here is this guide's label for the
repo's token set, not a name the source uses.

## Type
There is no type scale in the source. `tokens.tokens.json` has only `color`, `spacing` and
`radius` groups, and `design.md` only those three tables. No font family, size, weight or line
height is recorded, and this guide doesn't add one.

## Colour alone
The only rule on colour use in the repo's design-system records is the v4.1 snapshot's, for the
`status-indicator` component: "Icon+text pairing keeps the at-a-glance scannability color gave
without relying on color alone; intended to satisfy 1.4.1; not yet re-screened."
(`design-system/v4-1-status-indicator-component.md:31-33`). It's recorded for that component, which
has not been re-screened; this guide doesn't extend it to other components.
