# Setup

A step-by-step guide to getting this repo running locally: a git-and-Markdown UX research
knowledge base that an AI coding agent can query later, with a Figma-synced design tokens layer.
Commands and flags were checked by reading the scripts in `research/scripts/` and
`design-tokens/scripts/`; they haven't all been run, and the Figma and Windows steps haven't been
run at all. Run commands from the repo root unless a step says otherwise.

For what the repo is and why it's shaped this way, see
[`agentic-ux-research-repo-plan.md`](agentic-ux-research-repo-plan.md) and
[`decisions.md`](decisions.md). For the full script reference, see [`AGENTS.md`](../AGENTS.md).

---

## 1. What you're building

Two related problems, one repo:

1. **Research memory** — usability tests, interviews, and surveys get captured once and then
   forgotten. Six months later nobody can answer "did we already test this?" This repo gives an
   agent a place to look, with sourcing back to the original notes.
2. **Design ops** — Figma holds the canonical visual language, but it's opaque outside Figma.
   This repo exports it into git-tracked Markdown + DTCG-format JSON so an agent (and a human
   skimming git) can read it directly.

The repo has three layers:

| Layer              | Contents                                      | Mutability                                |
| ------------------ | --------------------------------------------- | ----------------------------------------- |
| **Raw**            | Session notes, participant lists              | Append-only — never edited after creation |
| **Synthesized**    | Per-topic findings, written in your own words | Living — revised as new evidence comes in |
| **Index / schema** | Tag glossary, generated index files           | Index files regenerated by script         |

Alongside those sit `analytics/` (quant evidence) and 20 deliverable folders (research plans,
personas, wireframes, ...). See [`README.md`](README.md) for the full layout.

## 3. Clone and create a virtualenv

```bash
git clone <repo-url> agentic-repo
cd agentic-repo
python3 -m venv .venv
source .venv/bin/activate
```

On Windows, see §9 for activation. `.venv/` is already in `.gitignore`.

---

## 4. Install dependencies

```bash
pip install -r requirements-dev.txt
```

`requirements-dev.txt` pulls in `requirements.txt` (the runtime dependencies: `python-frontmatter`,
`PyYAML`, `requests`, `python-dotenv`, ...) plus the test, lint and type-check tools. Install
`requirements.txt` alone only on a host that runs the scripts but never the checks.

---

## 5. Run the tests and checks

These are the same checks CI runs (`.github/workflows/ci.yml`):

```bash
pytest
ruff check .
mypy
python research/scripts/build_index.py --check
python research/scripts/build_search_ui.py --check
pip-audit -r requirements.txt
```

Both `--check` runs write nothing. `build_index.py --check` exits 1 if an index is stale, a tag
isn't in the glossary, a cross-link points at a missing file, or a raw session or component isn't
mapped in `research/projects.yml`; a clean run prints nothing. `build_search_ui.py --check` exits
1 if `research/search.html` would change.

## 7. Day-to-day workflow

### Start a research session

```bash
python research/scripts/new_research_session.py \
  --title "Onboarding flow usability test" \
  --type usability-test \
  --topic-slug onboarding-flow-usability-test \
  --tags onboarding,usability \
  --related-findings onboarding.md \
  --researcher "Your Name"
```

This creates `research/raw/<date>-<topic-slug>/` with `session-notes.md` and `participants.md`,
pre-filled with the frontmatter schema and TODO placeholders, and adds the folder to
`research/projects.yml` as `project-cross-cutting` (reassign it there once the project is known;
see [`projects.md`](projects.md)). It refuses to overwrite an existing folder for the same date
and slug. To try it without keeping the result, do it on a throwaway branch.

- `--type` for a raw session is one of `usability-test`, `interview`, `survey`,
  `contextual-inquiry`, `accessibility-audit`, `analytics`.
- `--date` defaults to today (`YYYY-MM-DD`).
- `--researcher` is optional. The `researcher:` key is always written; without the flag it's
  left empty.
- Other optional flags: `--related-components`, `--method-label`, `--participants-count`,
  `--participants-roles`.
- Unknown tags produce a warning, not an error.

To check tags against the glossary (`research/findings/tags.md`) before using them:

```bash
python research/scripts/new_research_session.py --check-tags-only "onboarding,made-up-tag"
```

It exits 1 if any tag is undefined.

### Create a deliverable file

Pass one of the 20 deliverable folder names as `--type`, plus `--slug`. To try it without keeping
the result, do it on a throwaway branch. Always pass `--no-prompt`
in a scripted or agent session, since the script otherwise prompts interactively for the folder's
extra fields:

```bash
python research/scripts/new_research_session.py --type personas \
  --title "Frontline Nurse — Ambient Scribe" --slug frontline-nurse-ambient-scribe \
  --tags persona,nursing,ambient-scribe,project-ambient-scribe --no-prompt
```

A deliverable carries its `project-*` tag in its own `tags` (a raw session gets its project from
`research/projects.yml` instead). `--type prototypes` also needs `--proto-type clickthrough|coded`. See `AGENTS.md` and
[`deliverable-types.md`](deliverable-types.md) for every flag and field.

### Refresh the index

After adding or editing a finding, analytics summary or deliverable:

```bash
python research/scripts/build_index.py
```

This regenerates `research/_index.md`, `analytics/_index.md`, and the `_index.md` in each
deliverable folder. Use `--check` (see §5) to validate without writing.

### Rebuild the search UI

```bash
python research/scripts/build_search_ui.py
```

This writes `research/search.html`, a self-contained page you open directly in a browser — no
server. It's a snapshot, so re-run it after adding content.

### Commit

Every synthesis is its own commit, and the message says what raw evidence triggered it. Never
rewrite files in `research/raw/` or `analytics/raw/`: if a raw note was wrong, add a correction
file in the session folder that references it. Name it `correction-YYYY-MM-DD.md`, give it the
standard raw frontmatter with a `date`, and quote what it corrects. It corrects that folder's
`session-notes.md` without replacing it. It shows next to the session in `search.html` once you
regenerate it, and in the CRUD UI record view and Ask's corpus once the corpus copy they read (the
one `AGENTIC_REPO_ROOT` points at) contains the file, since they run `export_records.py` live.

## 8. Connect Figma (optional)

The live Figma fetch has not been run against a real Figma file in this repo. These steps follow
the script's code and Figma's documentation.

`design-tokens/scripts/sync_figma_tokens.py` talks to the **Figma REST API only**; it doesn't use
the Figma MCP server. It reads three settings from the environment, or from a `.env` file in the
**current working directory** (loaded via `python-dotenv`):

| Variable             | Required | Meaning                                                                          |
| -------------------- | -------- | -------------------------------------------------------------------------------- |
| `FIGMA_TOKEN`        | Yes      | Personal access token                                                            |
| `FIGMA_FILE_KEY`     | Yes      | The file key: the path segment after `/design/` in the Figma file's URL          |
| `FIGMA_API_BASE_URL` | No       | REST API host. Defaults to `https://api.figma.com`; set it for Figma for Government |

Start from the template and keep `.env` in the repo root, since that's where you run the script
from (`.env` is git-ignored; never commit it):

```bash
cp .env.example .env    # then fill in FIGMA_TOKEN and FIGMA_FILE_KEY
```

The script's flags:

| Flag                        | Effect                                                              |
| --------------------------- | ------------------------------------------------------------------- |
| *(none)*                    | Full sync: variables + components                                   |
| `--skip-variables`          | Components only                                                     |
| `--skip-components`         | Variables only                                                      |
| `--regenerate-design-only`  | No network: rebuild `design.md` from the existing `tokens.tokens.json` |
| `--dry-run`                 | Fetch and transform, print what would change, write nothing         |

A real sync overwrites `design-tokens/tokens.tokens.json`, `design-tokens/design.md`, and the
generated parts of each `design-tokens/components/*.md` (the hand-written "Related Research
Findings" and "Notes" sections are preserved). In this repo those files hold fictional sample
content, so run with `--dry-run` first. A new component file also needs a line in
`research/projects.yml`, or `build_index.py --check` fails.

Pick the subsection that matches the Figma access you have.

### 8a. Commercial Figma: Enterprise vs. everything else

Per Figma's documentation, the Variables REST API requires a **Full seat in an Enterprise org**.
Free, Professional and Organization plans don't get it, even though the last two are paid; the
Variables scope won't appear in the token dialog below Enterprise. That's expected, not a bug.

1. **Generate a personal access token**: Figma → Account Settings → Personal access tokens →
   Generate new token.
   - Check **`file_content:read`** (scope name per Figma's documentation) — this lets the
     script read the file's document tree and find components. On Enterprise, also enable the
     Variables scope the dialog offers.
   - Leave everything else unchecked.
   - Figma shows the token once — copy it immediately.
   - Generate a fresh token for this project rather than reusing one, so you can revoke it
     independently later.
2. **Fill in `.env`** with `FIGMA_TOKEN` and `FIGMA_FILE_KEY`. If your components are published to
   a team library, point `FIGMA_FILE_KEY` at the library file itself: the script fetches one
   file's document tree.
3. **Run the sync.** Below Enterprise, skip the Variables endpoint:

   ```bash
   python design-tokens/scripts/sync_figma_tokens.py --skip-variables --dry-run
   python design-tokens/scripts/sync_figma_tokens.py --skip-variables
   ```

   On Enterprise, drop `--skip-variables` to sync variables into `tokens.tokens.json` as well.

### 8b. Figma for Government

`FIGMA_API_BASE_URL` is **not hardcoded**: the script reads it from the environment or `.env`
and falls back to `https://api.figma.com` only when it's unset. To use Figma for Government, set
`FIGMA_API_BASE_URL=https://api.figma-gov.com` in `.env`. Everything else about the REST path (auth, endpoints, response shapes) is
the same.

- **Variables are available.** Per Figma's documentation, Figma for Government includes the
  Enterprise feature set, so you shouldn't need `--skip-variables`.
- **Tokens work the same way.** Per Figma's documentation, Figma for Government requires SAML SSO
  to sign in, but once you're signed in, personal access tokens are generated through the same
  Account Settings flow as in 8a.
- **Network allowlisting.** Government environments often block outbound traffic by default; ask
  IT to allow HTTPS (port 443) to the Figma for Government domains.
- **If the variables call returns 403**, the script's error message reminds you to check
  `FIGMA_API_BASE_URL` and prints the host it actually called.
- **MCP is a separate question.** The script doesn't use MCP at all. Figma's documentation notes
  that its MCP service for Figma for Government isn't yet inside Figma's FedRAMP authorization
  boundary, so check with whoever owns your authorization boundary before pointing any MCP client
  at it.

Nothing in the repo records this path being run against a real Figma for Government tenant.

### 8c. Manual fallback (no API access)

Some environments won't issue a personal access token, block outbound calls to every Figma API
host, or restrict plugins. Then there's no automated sync, and you maintain the design-tokens
files by hand. The script's docstring documents this fallback. It's the one case where
`tokens.tokens.json` is hand-maintained; otherwise the sync generates it (see `AGENTS.md`).

1. **Read values in Figma's Dev Mode / Inspect panel.** No token, MCP or plugin needed.
2. **Hand-write `design-tokens/tokens.tokens.json`** in DTCG shape (`$value` / `$type` per token),
   matching the existing file's grouping so nothing downstream changes.
3. **Regenerate `design.md`** without touching the network:

   ```bash
   python design-tokens/scripts/sync_figma_tokens.py --regenerate-design-only
   ```

4. **For components**, hand-write one Markdown file per component under
   `design-tokens/components/`, copying the frontmatter and sections of an existing file there.
   There's no offline regenerate step for components: the script only writes them after
   fetching from Figma.
5. **Revisit once real access exists.** A later real sync overwrites the hand-maintained token
   values; the hand-written "Related Research Findings" and "Notes" sections in component files
   are kept.

## 9. Windows notes (untested on Windows)

CI runs on Ubuntu, and none of these steps has been verified on Windows. They are general Python
and git notes, not tested instructions. Git Bash and the standard Python installer are the assumed
baseline ([decision 9](decisions.md#9-windows-setup-docs-are-general-purpose-only)).

- **Virtualenv activation.** Create it with `python -m venv .venv`, then activate it with
  `.venv\Scripts\activate.bat` in Command Prompt or `.venv\Scripts\Activate.ps1` in PowerShell.
- **`python` vs. `python3`.** On Windows the interpreter is usually `python` (or the launcher,
  `py -3.13`); `python3` may not exist or may open the Microsoft Store. Substitute `python` in
  every command above. Inside an activated venv, `python` is the venv's interpreter on every OS.
- **PowerShell execution policy.** If `Activate.ps1` is blocked, allow local scripts for your
  user with `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, or for the current session
  only with `Set-ExecutionPolicy -Scope Process Bypass`. Check your organization's policy first.
- **Line endings.** The repo doesn't ship a `.gitattributes` file. With Git's default Windows
  setting (`core.autocrlf=true`), files are checked out with CRLF line endings, which breaks bash
  scripts such as `reset_demo.sh` and can produce whole-file diffs. Adding a
  `.gitattributes` with `* text=auto eol=lf` (or setting `core.autocrlf=input`) keeps LF endings.
- **bash-only pieces.** `reset_demo.sh` and `tests/test_reset_demo.py` need bash (for example
  Git Bash or WSL).
